# СверкаСмет (SmartMatcher)

> **Программный комплекс интеллектуального аудита и сопоставления строительной сметной документации (ВОР и ЛСР)**  
> Разработано в рамках выпускной квалификационной работы (ВКР / дипломного проекта).

---

## 📌 О проекте

Сверка **Ведомостей объёмов работ (ВОР)** и **Локальных сметных расчётов (ЛСР)** — один из самых трудоемких процессов строительного контроля и экспертизы смет. Различия в формулировках расценок, несовпадение единиц измерения (например, `100 м²` против `м²`), обобщенные нормативные названия (например, расценка *«Прибор или аппарат»* вместо конкретного щита) и разночтения в объемах приводят к высокой вероятности ошибок при ручной проверке.

**SmartMatcher** решает эту задачу с помощью гибридного двухуровневого подхода:
1. **Уровень 1 (Детерминированный алгоритм v2)**:
   - нормализация строительного текста и извлечение физических параметров (сечения кабелей, диаметры труб, марки оборудования);
   - приведение строительных единиц к базовым физическим размерностям (`units.py`);
   - глобальная оптимизация сопоставления с защитой от порядка строк (порядок-независимый алгоритм);
   - выявление коллизий: конкуренция близких расценок, скрытые расхождения характеристик, скачки объёмов.
2. **Уровень 2 (ИИ-арбитраж сложных коллизий)**:
   - привлечение большой языковой модели (**Alice AI LLM Flash** / Yandex AI Studio) только для неочевидных и спорных позиций;
   - три стандартизированных решения арбитра: `CONFIRM` (подтвердить выбор алгоритма), `REASSIGN` (переназначить на точного кандидата), `REJECT` (отклонить всех кандидатов);
   - интеллектуальное локальное кэширование ответов (`results/llm_cache.json`) для минимизации расходов и нулевого ожидания при повторных запусках.
3. **Человек в контуре (Human-in-the-loop)**:
   - интерактивный веб-интерфейс инженера-сметчика для подтверждения или корректировки решений с возможностью выгрузки отчета в CSV.
4. **Научный бенчмарк и оценка качества**:
   - генератор контролируемых синтетических искажений (`perturb.py`);
   - расчет метрик качества сопоставления (Precision, Recall, F1-macro, точность выявления расхождений) в сравнении с классическим базовым алгоритмом (`baseline_legacy.py`).

## 🚀 Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com/gsaryann/sverka.git
cd sverka
```

### 2. Установка зависимостей
Требуется **Python 3.10** или выше (рекомендуется Python 3.12).

```bash
pip install -r requirements.txt
```

### 3. Запуск веб-приложения

#### На Windows:
Просто запустите файл **`start_web.bat`** (двойным кликом или из консоли):
```powershell
.\start_web.bat
```

#### На Linux / macOS:
```bash
python web/web_app.py
```

После запуска откройте в браузере: **`http://127.0.0.1:5000`**.

> 💡 **Важно**: Основной алгоритм **SmartMatcher работает полностью локально и офлайн** — для него **не нужны** API-ключи и интернет! Вы можете сразу загружать `.xlsx` файлы или тестировать встроенные комплекты.

## 🔒 Чеклист подготовки к публикации и релизу (Production Security Checklist)

Перед публичной публикацией репозитория, развёртыванием на сервере или демонстрацией комиссии выполните обязательные шаги:

### 1. Ротация и отзыв тестовых API-ключей
- [ ] **Yandex Cloud & GigaChat:** Проверьте локальный `.env`. Если там использовались персональные ключи разработчика, **отзовите их в консоли провайдера** и создайте отдельные сервисные аккаунты с лимитами.
- [ ] **Исключение секретов из Git:** Убедитесь, что `.env` находится в `.gitignore` и случайно не попал в историю коммитов (`git status`, `git log -S "AQVN"`).

### 2. Защита сессий Flask (`SECRET_KEY`)
- [ ] **Скомпрометированный тестовый ключ:** В коде и истории разработки использовался дефолтный ключ `sverkasmet-secure-key-2026-b2b`. Он **скомпрометирован**! В продакшене **ОБЯЗАТЕЛЬНА** генерация нового уникального криптостойкого ключа (не менее 32 символов).
- [ ] Сгенерируйте криптографически стойкий 256-битный ключ:
  ```bash
  python -c "import secrets; print(secrets.token_hex(32))"
  ```
- [ ] Пропишите сгенерированный ключ в `.env`: `SECRET_KEY=<ваш_токен>`.
- [ ] При `ENV=production` система физически блокирует запуск сервера, если `SECRET_KEY` не задан или равен дефолтному.

### 3. База данных PostgreSQL 17
- [ ] **Версия СУБД:** Рекомендуется PostgreSQL 17 (поддержка директивы `SET transaction_timeout = '30s'` для предотвращения зависания долгих транзакций). Скрипт миграции совместим и с PostgreSQL 14–16 с предупреждением в логах.
- [ ] **Смена пароля:** Смените стандартный пароль `P@ssw0rd` на сложный пароль администратора СУБД.
- [ ] **Отключение демо-пользователя:** Установите в `.env` переменную `SEED_DEMO_USER=0` и `ENV=production`.
  - В этом режиме ядро `db.py` **полностью отключает** автоматическое создание `demo@sverkasmet.ru` с ролью `estimator`.
  - Все попытки неавторизованного сохранения проектов через API отклоняются с кодом `401 Unauthorized`.

### 4. Обезличивание сметных файлов
- [ ] Проверьте файлы в директории `data/`: убедитесь в отсутствии конфиденциальных данных реальных заказчиков, номеров договоров, паспортных данных и прямых контактных телефонов.

### 5. Очистка кэша и временных файлов
- [ ] Очистите локальные кэши перед созданием чистого архива проекта:
  ```bash
  # Удаление кэша Python
  Get-ChildItem -Path . -Include __pycache__ -Recurse -Force | Remove-Item -Recurse -Force
  ```

## 🚀 Быстрый запуск (Windows)

1. Установите **PostgreSQL 17** (если ещё не установлен).
2. Создайте базу данных `sverka_db`:
   ```bash
   createdb -U postgres sverka_db
   # либо через psql:
   # psql -U postgres -c "CREATE DATABASE sverka_db;"
   ```
3. Скопируйте `.env.example` в `.env` и укажите свой пароль в `DB_PASS` (а также при необходимости `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`).
4. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
5. Запустите веб-сервер двойным кликом или из терминала:
   ```bash
   start_web.bat
   ```
6. Откройте в браузере `http://127.0.0.1:5000/login`.
   - Для демо-входа задайте в `.env` `SEED_DEMO_USER=1` и `DEMO_USER_PASSWORD=<ваш_демо_пароль>`, затем используйте email `demo@sverkasmet.ru` и пароль из `DEMO_USER_PASSWORD` (роль `estimator`).

### Если пишет «Ошибка связи с сервером» или «База данных недоступна»

Проверьте по порядку:
1. **Окно сервера открыто:** `start_web.bat` запущен и не завершился с ошибкой.
2. **Служба PostgreSQL запущена:** проверьте в «Службах» Windows (`services.msc`, служба `postgresql-x64-17`) или подключитесь через `psql`.
3. **Пароль и параметры в `.env`:** убедитесь, что в `.env` указан верный `DB_PASS`, а база `sverka_db` создана.
4. **Проверка состояния через API:** откройте `http://127.0.0.1:5000/api/health` — при работающей БД ответ будет `{"ok": true, "db": true}` (при недоступной БД — `{"ok": true, "db": false}`).

## 💻 Запуск через командную строку (CLI)

### Сопоставление произвольной пары файлов:
```bash
python run_compare.py "data/ВОР.xlsx" "data/ЛСР.xlsx" "results/мой_отчет.csv"
```

#### Флаги управления ИИ-арбитражем (`run_compare.py` и `run_baseline.py`):
- `--llm`: включить двухуровневый гибридный режим сопоставления. SmartMatcher v2 выполняет предварительную фильтрацию и сопоставление, а нейросетевой арбитр (модель Алиса в Yandex AI Studio) привлекается только для разрешения сложных и спорных коллизий.
- `--llm-local`: включить локальный режим сопоставления через Ollama (OpenAI-совместимый эндпоинт). Документы не передаются во внешние облачные сервисы (взаимоисключим с `--llm`).
- `--llm-weak`: вызывать ИИ-арбитра исключительно для позиций с пограничной или слабой уверенностью алгоритмического ядра (`conf < 0.6`).
- `--llm-only`: экспериментальный режим «чистого» LLM-сопоставления без предварительного отбора SmartMatcher (используется для научных экспериментов и оценки способности LLM самостоятельно разбирать сметы с нуля).

### Локальный режим сопоставления (Ollama, полная конфиденциальность)

Для организаций с повышенными требованиями к информационной безопасности реализован режим **«SmartMatcher + локальная модель»**, в котором ни сметные документы, ни их позиции не покидают компьютер пользователя (отсутствуют сетевые обращения к внешним облачным сервисам).

#### 1. Установка и подготовка Ollama:
1. Скачайте и установите Ollama с официального сайта: [ollama.com](https://ollama.com).
2. Загрузите желаемую языковую модель с поддержкой инструкций (по умолчанию в проекте настроена `qwen2.5:7b-instruct`):
   ```bash
   ollama pull qwen2.5:7b-instruct
   ```
   *(Требования к оперативной памяти и видеопамяти зависят от выбранной модели и её квантования: например, для 7B моделей требуется от 8–16 ГБ RAM/VRAM, для более компактных моделей 3B — меньше).*
3. Убедитесь, что сервер Ollama запущен (по умолчанию эндпоинт доступен по адресу `http://localhost:11434`).

#### 2. Конфигурация окружения (`.env`):
В файле `.env` задаются параметры подключения:
```env
# Адрес локального сервера Ollama (OpenAI-совместимый эндпоинт)
LOCAL_LLM_BASE_URL=http://localhost:11434/v1

# Имя загруженной модели в Ollama
LOCAL_LLM_MODEL=qwen2.5:7b-instruct

# Таймаут ожидания ответа модели в секундах (по умолчанию 120)
LOCAL_LLM_TIMEOUT=120
```

#### 3. Использование локального режима:
- **В веб-интерфейсе:** в выпадающем списке «Режим сопоставления» выберите **«SmartMatcher + локальная модель (Ollama, без передачи документов)»**.
- **В командной строке (CLI):** передайте флаг `--llm-local` (взаимоисключим с облачным флагом `--llm`):
  ```bash
  python run_compare.py "data/ВОР.xlsx" "data/ЛСР.xlsx" --llm-local
  ```
- **Стоимость использования:** 0.00 ₽ (локальные вычислительные ресурсы пользователя).

### Запуск экспериментов и сравнительного бенчмарка:
```bash
# Базовый запуск сравнения SmartMatcher против baseline
python run_baseline.py --compare "data/ВОР.xlsx" "data/ЛСР.xlsx"

# Сравнение гибридного режима с LLM против baseline
python run_baseline.py --compare "data/ВОР.xlsx" "data/ЛСР.xlsx" --llm
```

### Запуск набора модульных тестов:
```bash
python -m unittest discover -v
# или через pytest:
pytest -q
```
*(Проект содержит **92 автоматических теста** (79 автономных модульных и 13 интеграционных для СУБД, а также 12 параметризованных подтестов), покрывающих:*
- *расчёт финансовых рисков и пересчёт объёмов (`test_risk_calculation.py`);*
- *безопасность Web-слоя, RBAC, защиту от инъекций и rate limiting (`test_security.py`);*
- *транзакции, триггеры и целостность базы данных (`test_db_and_projects.py`);*
- *устойчивость парсеров Excel и сброс кэшей синтетических возмущений (`test_core_and_parsers.py`);*
- *алгоритмическое ядро сопоставления и физические единицы (`test_suite.py`);*
- *защиты вокруг LLM-резолвера и валидацию JSON (`test_llm_resolver.py`);*
- *интеграционные сценарии авторизации и сессий (`test_auth_db.py`, `test_web_api_auth.py`)*.

> 💡 **Запуск без PostgreSQL**: Все тесты базы данных изолированы. Если локальная СУБД PostgreSQL не запущена или недоступна, тесты авторизации и персистентности автоматически и безопасно пропускаются через `unittest.SkipTest`, гарантируя успешное прохождение всех 79 тестов основного алгоритма, безопасности и парсеров в любых окружениях (CI/CD, локальная разработка).
>
> ⚙️ **Требования к СУБД PostgreSQL**: Для работы модуля проектов и персистентности требуется **PostgreSQL 17** (в `schema.sql` используется параметр `SET transaction_timeout = 0`, появившийся в версии 17). База данных инициализируется автоматически при первом запуске приложения (`init_db()`), либо вручную через `psql -f schema.sql`.

### Воспроизводимые отчеты и метрики ВКР:
В каталоге `tools/` размещены скрипты генерации доказательной базы:
- **`python tools/risk_report.py`** — выполняет расчет финансовых рисков на всех реальных парах смет и сохраняет детализированный аудит в `docs/metrics/` (актуальный файл: [`docs/metrics/risk_13d8b18.md`](docs/metrics/risk_13d8b18.md)).
- **`python tools/collect_metrics.py`** — запускает сравнительный бенчмарк алгоритмов (SmartMatcher v2 vs Baseline Legacy) на 4 комплектах смет при 3 seeds с сохранением порядка и при перемешивании (`--shuffle`), формируя сводку средних, анализ устойчивости к порядку и диагностику коллизий в `docs/metrics/` (актуальный файл: [`docs/metrics/f1_8b933a4.md`](docs/metrics/f1_8b933a4.md)).
