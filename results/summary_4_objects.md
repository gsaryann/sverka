## 3. Исследование влияния веса объема: `w_q = 0.1` против `w_q = 0.0` (Шаг 3)

Проверка проведена без модификации кодовой базы проекта через временный скрипт вызова `match.match(..., w_q=0.1)`. 

### Сравнительные результаты «Было / Стало»

| Пара / Объект | Спорных позиций (детектор) | Класс «Расхождение объёма» | Класс «Совпало» | Класс «Совпало (с пересчетом)» | Классы «Нет в смете / Нет в ВОР» |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Пара 1** (Дворец молодёжи) | 26 → 26 *(без изм.)* | 1 → 1 *(без изм.)* | 47 → 47 *(без изм.)* | 22 → 22 *(без изм.)* | 16 / 16 *(без изм.)* |
| **Пара 2** (Кристалл освещение) | 100 → 100 *(без изм.)* | **47 → 0 (-47)** | **90 → 137 (+47)** | 0 → 0 *(без изм.)* | 0 / 0 *(без изм.)* |
| **Пара 3** (Калуга, Вилонова) | 526 → 526 *(без изм.)* | **126 → 0 (-126)** | **408 → 534 (+126)** | 0 → 0 *(без изм.)* | 0 / 0 *(без изм.)* |
| **Пара 4** (ККБ пом. 163) | 12 → 12 *(без изм.)* | **4 → 0 (-4)** | **44 → 48 (+4)** | 35 → 35 *(без изм.)* | 0 / 0 *(без изм.)* |

### Анализ механизма влияния `w_q`:
1. **Устранение ложных расхождений объема:** В Парах 2, 3 и 4 присутствует множество одинаковых работ в разных помещениях, отличающихся объемами. При `w_q = 0.0` венгерский алгоритм ориентируется исключительно на семантическое сходство текста, произвольно спаривая одинаковые названия из разных помещений (например, работу с объемом 10 м² в каб. 1 с работой на 15 м² в каб. 2), что порождало ложные «Расхождения объёма». Добавление веса `w_q = 0.1` выступает в качестве решающего критерия при равенстве текстовых скоров (tie-breaker): алгоритм связывает строки с идентичными объемами, переводя все ложные расхождения в класс «Совпало».
2. **Почему число спорных позиций не изменилось:** Детектор неоднозначностей оценивает наличие близких кандидатов-конкурентов по текстовому сходству (порог маржи 0.12). Поскольку одинаковые наименования работ физически присутствуют в документе по несколько раз, детектор продолжает справедливо квалифицировать их как «competition» (конкуренция дублей).

## 4. Выявленные аномалии и технические замечания

1. **Аномалия числа записей в Паре 1 (102 записи при 86 позициях):**  
   В Паре 1 сметные объемы ВОР и ЛСР не совпадают полностью: 70 позиций сформировали взаимные пары, а 16 позиций ВОР и 16 позиций ЛСР остались без пары. В итоговый CSV-отчет выводятся как пары ВОР-ЛСР (70 строк), так и несопоставленные позиции ВОР («Нет в рассматриваемой смете», 16 строк), и несопоставленные позиции ЛСР («Нет в ВОР», 16 строк): $70 + 16 + 16 = 102$ записи. В остальных комплектах (Пары 2, 3, 4) соответствие взаимно однозначное (1:1).

2. **Аномально высокая доля спорных позиций на крупных объектах:**  
   В Паре 3 (534 позиции) выявлено **526 спорных позиций (98,5%)**, в Паре 2 (137 позиций) — **100 спорных позиций (73,0%)**.  
   *Причина:* в смете на ремонт здания (ул. Вилонова) одни и те же технологические операции (демонтаж плинтусов, снятие обоев, затаривание мусора) расписаны по десяткам отдельных кабинетов (Кабинет №3, Кабинет №4, Коридор и т.д.). В отсутствие предварительной фильтрации по разделам/помещениям алгоритм видит десятки полных текстовых дубликатов. Это служит строгим эмпирическим доказательством необходимости внедрения пространственной фильтрации (по разделам/этажам), отмеченной в п. 4.8 диплома.

3. **Особенности номенклатуры классов в коде:**  
   Класс с пересчетом единиц в кодовой базе записан как `Совпало (с пересчетом единиц)` (со скобками и буквой «е»). В Паре 1 таких позиций 22, в Паре 4 — 35.
